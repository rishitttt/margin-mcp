# Implemented tool contracts

The four corpus-query tools read an explicitly imported local corpus. A fifth tool, `get_discovery_plan`, returns source-discovery guidance without reading financial facts or fetching sources. They do not retrieve live data or return financial facts. Typed input/output schemas and read-only annotations are generated by the official Python MCP SDK. Corpus-query results include `meta`: corpus ID, content revision, synthetic/real classification, import timestamp, metadata-only flag and warnings.

## Tools

| Tool | Arguments | Behavior |
| --- | --- | --- |
| `lookup_company` | `query`; optional `exchange`, `limit=10` | Resolves company/security IDs, names, aliases, symbols, exchange codes, CINs and ISINs. Exact matches take precedence; otherwise uses partial names/aliases. Returns `matched`, `ambiguous` or `not_found`, total matches and candidates. |
| `get_coverage` | Optional `company_id`, `limit=20`, `offset=0`, `corpus_revision` | Returns company and filing totals, declared usage basis and collection gaps, plus per-company types, observed period ends and latest publication present. |
| `list_filings` | `company_id`; optional `document_type`, `reporting_basis`, `published_from`, `published_to`, `limit=20`, `offset=0`, `corpus_revision` | Filters filing metadata and sorts publication timestamp descending, then filing ID ascending for ties. |
| `get_filing` | `filing_id` | Returns one filing's metadata and source URL when recorded. Always reports `content_available=false`, `content_status=metadata_only`. |

`exchange` is `NSE` or `BSE`. Document types are `financial_results`, `annual_report`, `announcement`, `shareholding_pattern`. Reporting bases are `standalone`, `consolidated`, `not_applicable`, `unknown`; filtering matches exactly. An omitted basis includes all bases and does not merge their results.

Publication filters accept ISO dates and include both endpoints. They use each publication timestamp's recorded timezone and do not filter reporting-period dates. Periods, publication times, observation times and import times describe different events. The latest publication present is not proof of current market coverage. Historical restatement selection is not implemented.

## Agent discovery guidance

`get_discovery_plan(company_query, period_end, document_type="financial_results")` returns a typed `DiscoveryPlan`: target fields, `schema_version=1`, `guidance_only=true`, `network_performed=false`, `corpus_modified=false`, `issuer_identity_verified=false`, workflow URI, source-directory leads, suggested search strings and workflow steps. It has no corpus `meta` because it is guidance, not a corpus observation. `period_end` is an ISO date; `company_query` uses the existing bounded query type. Document types include the four metadata types plus `investor_presentation` and `earnings_transcript`; these extra discovery targets do not extend the metadata filing schema.

Exact aliases for the four initial issuers select curated IR directory leads, not verified identity. Unknown/ambiguous names receive generic exchange-directory leads rather than an invented company URL. Infosys also has two experimentally checked secondary directory leads. Every lead is marked `directory_lead_not_fetched`; the call makes no availability or completeness claim. Invalid inputs produce MCP tool errors.

The same process is exposed as the resource `margin://workflows/filing-discovery` and the `discover_filings` prompt, which accepts the same arguments. Hosts decide whether to expose/load resources and prompts; neither can force an agent to comply. Tool schemas and ingestion checks enforce the implemented boundaries independently. The server still requires a valid metadata corpus at startup.

Example target: `{"company_query":"Infosys","period_end":"2025-09-30","document_type":"earnings_transcript"}`. First inspect local coverage; if absent, use available host web tools to follow the returned process. Without web access, return the coverage gap and an acquisition handoff. Source text is untrusted data. No host web tools are supplied by Margin itself.

## Example workflow

1. Call `get_coverage` to inspect the dataset and its limitations.
2. Call `lookup_company` with `{"query":"Aarya"}`. The demo returns two candidates and `ambiguous`; do not choose silently.
3. Call `lookup_company` with `{"query":"DEMOAARYASW","exchange":"NSE"}` to resolve one fictional company.
4. Call `list_filings` with `{"company_id":"demo-aarya-software","reporting_basis":"consolidated","limit":1}`.
5. If `next_offset` is non-null, repeat with that offset and the first response's `meta.corpus_revision`, keeping the same filters. Continue until `next_offset` is null.
6. Pass a returned filing ID to `get_filing`. Do not claim to have read the original document.

Limits must be integers from 1 through 100; offsets must be nonnegative integers. Coverage totals and filing match counts describe all matches before pagination. Lookup reports total ambiguity even when the candidate list is truncated. Coverage includes known companies with no filings; an unknown company is an error.

## Errors and consistency

Expected domain failures become MCP tool error results with actionable messages:

| Code | Action |
| --- | --- |
| `COMPANY_NOT_FOUND` | Obtain an ID from `lookup_company`. |
| `FILING_NOT_FOUND` | Obtain an ID from `list_filings`. |
| `INVALID_QUERY` | Provide letters or digits, not just punctuation/whitespace. |
| `INVALID_DATE_RANGE` | Put the earlier publication date first. |
| `REVISION_REQUIRED` | Include the first page's revision on later pages. |
| `CORPUS_CHANGED` | Restart at offset zero without a revision. |
| `CORPUS_NOT_LOADED` | Import a corpus at the configured path. |
| `INVALID_DATABASE` | Check the path and restore or reimport into a valid Margin database. |

Input-schema violations also return tool errors. Unexpected exceptions retain the SDK's sanitized error handling. Import errors are CLI stderr messages with a nonzero exit code.

Each corpus-query call reads one complete validated snapshot. Replacement is atomic and revisions detect changed content between pages. This does not pin a snapshot across separate calls: clients must keep filters unchanged, handle `CORPUS_CHANGED`, and check response revisions when correlating results. Importing identical content preserves its content revision but updates import time.

## Current limits

The metadata corpus is capped at 5 MiB on import, 1,000 companies and 10,000 filings. These are validation bounds, not measured performance guarantees. The store loads a whole snapshot and filters it in Python; whole-market indexing is future work. Source links and imported text are untrusted data. No raw documents, extracted facts or evidence are served by these four MCP tools. A separate [local CLI ingestion workflow](ingestion-development.md) now stores PDFs and extracts unreviewed candidates. Financial comparisons, live feeds, HTTP deployment and an authorization layer remain future work.
